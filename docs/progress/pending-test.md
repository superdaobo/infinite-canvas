# 待测试

- 共享房间画布只读入口（C02-01）：登录后访问 `/canvas/rooms/:roomId` 可通过 `GET /api/v1/collab/rooms/:id/graph` 加载房间公共图并只读渲染；该路由与单人项目 `/canvas/:id` 使用独立状态边界，不会写入个人画布本地存储或个人项目接口。可用 `NEXT_PUBLIC_ENABLE_CANVAS_COLLAB=false` 关闭共享入口回退单人体验。
- 共享房间实时接收（C02-03）：`/canvas/rooms/:roomId` 会用 `POST /api/v1/collab/rooms/:id/ws-ticket` 换取一次性 ticket，再连 `GET /api/v1/collab/rooms/:id/ws` 并发送首帧 `hello`（协议版本校验）。收到 `snapshot-*` 分帧快照、`changes` 增量、`presence` 在线成员、`cursors` 协作光标与 `error` 后更新画布；断网/切标签页后按当前 revision 自动重连并补发未确认操作，重连期间本地未确认草稿不清空。权限被撤销（4401/4403 或 `unauthorized`/`forbidden` 等错误码）后页面显示访问失效并停止接受广播。前后端分离开发时可用 `NEXT_PUBLIC_COLLAB_WS_BASE`（如 `ws://127.0.0.1:8080`）指向 Go 后端 WS 端点。
- 共享房间成员与分享管理 UI（C02-05）：`/canvas/rooms/:roomId` 顶部新增「成员与分享」入口，任何成员可查看成员列表；owner 可改成员角色（可编辑/只读）、移除成员、生成邀请链接（选角色 + 有效期 1/3/7/30 天）、查看邀请状态并撤销、复制邀请链接。邀请链接为 `/canvas/rooms/:roomId#invite=<token>`（令牌放 URL fragment，读取后立即清除，不进服务端日志）；打开邀请链接未登录时先跳登录/注册，登录后自动调用 `POST /api/v1/collab/invites/accept` 加入房间。viewer 不显示可写操作入口，非 owner 不显示成员管理入口（后端仍按 `docs/collab-v1/security-boundaries.md` 矩阵二次鉴权）。
- 协作历史审计与撤销/重做（C01-06，仅服务端）：每次成功操作批次写入 `collab_room_history`（含操作者、时间、批次 operationId、前后版本与逐目标快照）。`GET /api/v1/collab/rooms/:id/history` 返回审计列表；`POST .../history/:historyId/undo`、`.../redo` 按用户隔离撤销/重做自己的操作（节点与关联连线一起恢复/移除），切换时以行版本做条件 CAS；若相关节点/连线已被他人修改则返回 `version_conflict`（`reason=history_invalidated`）且不覆盖他人修改。连续拖动（仅改坐标的 update）会合并为一条历史。前端撤销 UI 属 C01-06 之外（#15）。
- 房间媒体分片上传（C04-03，仅服务端）：为突破 Cloudflare 100MB 请求体上限，新增分片上传会话：`POST /api/v1/collab/rooms/:id/media/uploads`（声明 filename/contentType/totalBytes/sha256）→ `PUT .../media/uploads/:sessionId/chunks/:index`（按序号上传，末片可小于服务端返回的 `chunkBytes`）→ `POST .../media/uploads/:sessionId/complete`（按序合并 + 校验总大小与 SHA-256 摘要后登记，响应与单请求上传同构）。`GET .../media/uploads/:sessionId` 查询进度（已收分片数/字节数），`DELETE` 取消并回收临时分片，会话 24 小时过期后由每日清理任务回收。重复分片与重复完成幂等，分片可乱序/并发上传；缺分片、摘要不符、超上限、非法类型、非成员/只读成员分别返回 409/400/413/415/404/403。小文件仍可走既有单请求 `POST .../media` 路径（上限 64 MiB，未改动）；大文件读取继续支持 HTTP Range 与 `nosniff`。
- 共享房间学校队列状态与个人取消（C03-06）：`/canvas/rooms/:roomId` 顶部新增「学校队列」入口，打开后按固定间隔轮询 `GET /api/v1/collab/rooms/:id/school-tasks` 展示全房间共享的 FIFO 队列（排队位置、提交人昵称、渠道、状态、当前唯一执行中任务）。仅本人提交且状态为 `queued` 的任务可取消（`POST .../school-tasks/:taskId/cancel`），他人或已开始任务给出不可取消说明；owner/editor 可见提交表单（可选图片/视频渠道并显示排队结果），viewer 只读。执行器异常（队列有人在等但无执行设备、执行中任务超过约 3 分钟未推进、最近失败原因、设备重新绑定恢复）以中文提示呈现，仅作前端提示，不改变后端真实状态，也不把设备离线误报为任务已取消。
- 共享房间 config/director 节点渲染（#65）：`/canvas/rooms/:roomId` 中 `config` 节点渲染与单人模式一致的生成配置面板（模式/模型/参数可编辑并写入房间公共图），`director` 节点渲染「打开导演台」入口并可打开真实 3D 导演台（项目结构写回节点 `directorProject`，删除全景引用会断开对应连线），不再回落为「空图片节点」。共享房间不支持直接生成，也不支持把导演台截图/视频写回画布（媒体为本地大对象，超出节点 metadata 1MiB 契约）：点击「开始生成」「组装提示词」或截图/视频回传时以中文提示引导到单人画布；viewer 只读时配置改动不落库。
- 安全审计与高危修复（C05-02）：新增审计报告 `docs/collab-v1/security-audit.md`（N1–N18 逐项结论）。修复三组问题：(1) `GET /api/proxy-image` 不再回显上游 `text/html`/`image/svg+xml` 等主动内容，统一降级为 `application/octet-stream` + 附件下载并加 `X-Content-Type-Options: nosniff`；(2) `GET /api/files/:id/content` 对存储的主动内容同样降级为附件下载并加 `nosniff`（图片/视频/音频/PDF 仍内联，单人模式正常素材展示不受影响）；(3) 账号封禁/删除后主动关闭其全部房间 WS 连接（4401），且封禁前签发的未使用 WS ticket 建连即被拒（4403）。可用 `go test ./handler/ -run TestProxyImageNeutralizesActiveUpstreamContent` 与 `go test ./router/ -run 'TestWSDisconnectOnAccountBan|TestWSConnectRejectedForBannedAccount'` 验证。
